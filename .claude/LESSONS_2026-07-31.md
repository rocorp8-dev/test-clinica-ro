## 📚 Lecciones Clave

### 1. Cambios Quirúrgicos = Mínimo Impacto

**Problema:** Usuario tiene sistema en producción con doctores activos.

**Solución aplicada:**
- ✅ Solo 3 cambios en 1 archivo (`PatientDetailModal.tsx`)
- ✅ Campo condicional (no afecta otros tipos de nota)
- ✅ Migración con `IF NOT EXISTS` (idempotente)
- ✅ Campo nullable (no rompe datos existentes)

**Lección:** Cuando el sistema está en producción, hacer cambios **aditivos** nunca **destructivos**.

```typescript
// ✅ CORRECTO: Agregar sin afectar existente
const SOAP_INITIAL = { ...campos_existentes, antecedentes_go: '' }

// ❌ INCORRECTO: Modificar estructura existente
const SOAP_INITIAL = { nuevo_formato_que_rompe_todo }
```

---

### 2. Condicionalmente Visible = Mejor UX

**Implementación:**
```tsx
{soap.tipo_nota === 'primera_vez' && (
    <div className="pt-2 border-t border-white/10">
        <textarea ... />
    </div>
)}
```

**Por qué funciona:**
- ✅ Solo aparece cuando es relevante
- ✅ No confunde en otros tipos de nota (Evolución, Urgencias, etc.)
- ✅ Destaca visualmente con color diferente (pink vs emerald)

**Lección:** Campos especializados deben aparecer **solo cuando aplican**.

---

### 3. Estilo Diferenciado = Claridad Visual

**Código:**
```tsx
// Campo GO (rosa/pink)
className="bg-pink-500/10 border-pink-300/30 focus:ring-pink-400/40"

// Campos SOAP estándar (blanco/neutro)
className="bg-white/10 border-white/20 focus:ring-emerald-500/40"
```

**Por qué funciona:**
- ✅ Usuario identifica inmediatamente que es sección diferente
- ✅ No confunde con campos SOAP regulares
- ✅ Color rosa = connotación ginecológica/obstétrica

**Lección:** Usar **color como affordance** para indicar contexto diferente.

---

### 4. Migraciones Idempotentes = Seguridad

**SQL aplicado:**
```sql
ALTER TABLE medical_notes
ADD COLUMN IF NOT EXISTS antecedentes_go text;
```

**Por qué `IF NOT EXISTS`:**
- ✅ Puede ejecutarse múltiples veces sin error
- ✅ No falla si columna ya existe
- ✅ Seguro para CI/CD y deploys repetidos

**Lección:** Siempre usar `IF NOT EXISTS` / `IF EXISTS` en migraciones.

---

### 5. Verificar Build Antes de Commit

**Proceso seguido:**
1. Hacer cambios en código
2. Ejecutar `npm run build`
3. Verificar que compila sin errores
4. Ejecutar migración en Supabase
5. Commit y push

**Lección:** Nunca pushear sin verificar que el build pasa.
